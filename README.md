# Vantage — Personalized Banking Assistant for SMBs

A full-stack banking platform with an embedded AI assistant that gives small
and medium business (SMB) clients personalized financial insights, transaction
summaries, and compliance alerts — built to match the "Personalized Banking
Assistant for SMBs" project brief.

> **Rename freely.** "Vantage" is just a working name given during development — rename it in the sidebar (`frontend/src/components/Sidebar.jsx`), the FastAPI title (`backend/app/main.py`), and Flutter app title (`mobile/lib/main.dart`) to whatever you'd like to submit under.

---

## 1. What's inside

```
banking-assistant/
├── backend/        FastAPI + SQLite REST API (auth, accounts, transactions, AI assistant, compliance)
├── frontend/        React web dashboard (Vite)
└── mobile/          Flutter mobile app (login, dashboard, AI chat)
```

## 2. How this maps to the original project spec

| Spec requirement | Implementation | Notes |
|---|---|---|
| Fine-tuned GPT-4 / LLaMA-2 assistant | `backend/app/mock_ai.py` — rule-based + pandas-driven NLG engine | See **Section 5** below — this is the one deliberate scope trade-off, explained fully so you can present it confidently. |
| FastAPI + PostgreSQL backend | FastAPI backend, **SQLite** by default | SQLite needs zero setup for a demo. Swapping to PostgreSQL is a one-line change (see `backend/app/database.py`). |
| Pandas / NumPy data processing | Transaction summarization in `mock_ai.py` uses pandas groupby/aggregation | |
| React.js web dashboard | `frontend/` — full dashboard, transactions, transfers, admin panel | |
| Flutter mobile app | `mobile/` — login, dashboard, AI chat screens | |
| AES encryption / RBAC | JWT auth + bcrypt password hashing + role-based route guards (`smb_client` vs `bank_admin`) | Passwords are hashed; for a full production system you'd also encrypt data at rest (AES) and use HTTPS/TLS in transit. |
| KYC/AML compliance monitoring | `check_compliance()` in `mock_ai.py` auto-flags large/unusual transactions; admin panel to review & resolve | |
| Multilingual support | English / Hindi / Telugu built into both the assistant replies and the UI | Easy to extend — see Section 6. |
| Cloud deployment (AWS/GCP/Azure) | Not deployed here | Deployment steps outlined in Section 7 if you want to actually host it. |

## 3. Running the backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Populate demo data (creates 1 admin + 2 SMB users with sample transactions)
python seed.py

# Start the API
uvicorn app.main:app --reload --port 8000
```

The API will be live at **http://localhost:8000**, with interactive docs at
**http://localhost:8000/docs** (auto-generated by FastAPI — great for your
project demo/viva, since you can show every endpoint working live).

## 4. Running the web frontend

```bash
cd frontend
npm install
npm run dev
```

Open **http://localhost:5173**. Make sure the backend is running first — the
frontend calls it at `http://localhost:8000` (configurable in `frontend/src/api.js`).

## 5. Running the mobile app

```bash
cd mobile
flutter pub get
flutter run
```

Requires the [Flutter SDK](https://docs.flutter.dev/get-started/install) installed locally (not something this environment can install/verify, so test it on your own machine).

Before running, set the correct backend URL in `mobile/lib/services/api_service.dart`:
- **Android emulator:** `http://10.0.2.2:8000` (already the default)
- **iOS simulator / physical device:** replace with your computer's local IP, e.g. `http://192.168.1.5:8000`

## 6. About the "mock AI" assistant — what to say in your report

The original spec calls for a fine-tuned GPT-4/LLaMA-2 model. That's not
practical for a college project (needs GPU infra, labeled training data, and
ongoing API cost). Instead, `mock_ai.py` implements a **rule-based NLG engine**
that:

- Pulls **real transaction data** from the database via pandas
- Detects user intent via keyword matching (balance, spending, compliance, history)
- Generates natural-sounding, personalized responses **from real numbers**, not canned text
- Responds in the user's chosen language (English/Hindi/Telugu)
- Includes a clearly-marked "swap-in" code path at the bottom of the file
  showing exactly how to plug in a real LLM API call later

This is an honest, defensible engineering decision — present it as a
deliberate trade-off (which it is) rather than hiding it. Evaluators generally
respond well to students who understand *why* they scoped something down.

**If you do get an API key later** (OpenAI, Anthropic, etc.), swapping in a
real model only requires changing the body of `generate_reply()` — the
function signature, the calling code in `routers/assistant.py`, and the
frontend all stay exactly the same.

## 7. Adding more languages

UI strings live in `frontend/src/i18n.js`, and assistant reply strings live in
`backend/app/mock_ai.py` under `TRANSLATIONS`. Add a new language code (e.g. `ta`
for Tamil) to both dictionaries and it'll show up automatically in the language
selector.

## 8. If you want to actually deploy this (optional, for extra credit)

- **Backend:** Deploy on Render, Railway, or a small AWS EC2/GCP Compute
  instance. Switch `backend/app/database.py` to PostgreSQL (Render/Railway
  both offer free managed Postgres).
- **Frontend:** `npm run build` produces a static `dist/` folder deployable to
  Vercel, Netlify, or an S3 + CloudFront bucket.
- **Mobile:** Build APK with `flutter build apk` for Android testing.

## 9. Security notes for your report

- Passwords are hashed with **bcrypt** (never stored in plaintext)
- Authentication uses **JWT** bearer tokens with an 8-hour expiry
- **Role-based access control** — the admin/compliance endpoints
  (`/compliance/*`) reject any request from a non-`bank_admin` user with a 403
- `SECRET_KEY` in `backend/app/auth.py` is a placeholder — in a real deployment
  this should come from an environment variable, never hardcoded
